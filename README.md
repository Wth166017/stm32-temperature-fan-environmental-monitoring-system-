# STM32 智能风扇温控系统

> 基于 STM32F103C8T6 的环境温度监测 + 自动风扇控制项目
> **DS18B20 数字测温 → OLED 实时显示 → 超阈值自动开风扇（滞回控制）+ LED 闪烁
> 支持按键菜单调参、蓝牙手机指令远程控制、串口周期上报**

---

## 📖 项目简介

一个面向 STM32 入门者、由浅入深迭代出来的综合练习项目：

- 用 **DS18B20 数字温度传感器**（单总线）采集环境温度，精度高、抗干扰
- **OLED 屏幕**实时显示温度、风扇状态和可调参数菜单
- 温度超过启动阈值自动开风扇（直流电机模拟），降到停止阈值以下关闭——**滞回控制**，避免临界频繁启停
- 风扇运行时 **LED 非阻塞闪烁**
- **双按键菜单**：本地切换/调节启动阈值、停止阈值、风扇速度
- **JDY-31 蓝牙**：手机发送文本指令即可远程修改阈值和速度
- **串口周期上报**温度（间隔可调，不刷屏）
- 所有参数集中在 `config.h`，驱动与业务分层，方便扩展

> 🌱 项目第一版使用 NTC 热敏电阻（ADC + B 值公式）测温，后迭代为 DS18B20 数字传感器。
> 旧 NTC 驱动 `Temperture Sensor.c` 保留在工程中备查（已不调用），可清楚看到迭代过程。

## ✨ 功能特性

- [x] DS18B20 单总线数字测温（默认 12 位分辨率，0.0625℃）
- [x] OLED 实时显示温度（含小数）、风扇状态、参数菜单

- [x] **非阻塞 LED 闪烁**（定时器节拍，不卡死主循环）
- [x] **双按键菜单**：短按切换/调节，长按恢复默认（含消抖）
- [x] **蓝牙 SPP 透传**：手机文本指令远程改阈值/速度并回复确认
- [x] **串口周期上报**温度，上报间隔可配置
- [x] 参数集中管理（`config.h`），驱动/业务分层、模块独立

## 🚀 快速开始

### 环境要求
- Keil MDK（本工程基于 ARMCC V5.06）+ STM32F1xx 器件包
- ST-Link / J-Link 下载器
- 手机端：安卓手机 + 任意「蓝牙串口助手」类 APP（SPP 协议）

### 步骤
1. 克隆本仓库：
   ```bash
   git clone git@github.com:Wth166017/stm32-temperature-fan-environmental-monitoring-system-.git
   ```
2. 用 Keil 打开 `project.uvprojx`
3. 按实际接线核对 `System/config.h` 的引脚与参数
4. 编译（F7）、下载（F8）到板子，上电即运行
5. （蓝牙）手机配对 `JDY-31-SPP`（默认密码 `1234`），打开蓝牙串口 APP 连接后发送指令

## 📱 蓝牙指令协议

采用**文本模式（非 HEX）+ 可变包长 + `\n` 结束**，指令大写：

| 手机发送 | 含义 | 单片机回复 |
|---------|------|-----------|
| `ON32\n` | 风扇启动阈值 = 32℃ | `OK ON\r\n` |
| `OFF28\n` | 风扇停止阈值 = 28℃ | `OK OFF\r\n` |
| `SPD60\n` | 风扇速度 = 60% | `OK SPD\r\n` |
| 其他 | 无法识别 | `ERROR\r\n` |

**手机 APP 设置**：编码 UTF8、勾选「换行符 0x0A(\n)」、不勾 HEX。

> 为什么用文本而不是 HEX？指令少、人机交互、蓝牙链路自带 CRC 校验重传；文本可读、好调试。
> 为什么用可变包长而不是固定包长？以 `\n` 分隔，命令长短随意，以后加新命令不用改框架。

### 处理流程
中断逐字节接收 → 遇 `\n` 标记一行完整 → 主循环 `Serial_GetLine()` 取走
→ `strncmp` 识别命令头 → `ParseNumber()` 提取数字 → 限幅 + 滞回保护 → 执行并回复确认。

## 🧠 工作原理

### DS18B20 单总线测温
- 单总线协议：一根 DQ 线双向通信，开漏输出 + 上拉电阻
- 流程：复位脉冲（等待传感器应答）→ ROM 命令 `0xCC`（跳过 ROM）→ 功能命令
  - `0x44`：启动温度转换（等待约 800ms）
  - `0xBE`：读取暂存器（温度寄存器 2 字节）
- 换算：`温度 = 原始值 × 0.0625℃`（12 位分辨率）
- 驱动用三状态状态机 + `TickCount` 非阻塞等待转换，不卡死主循环

### 滞回控制（Hysteresis）
```
温度 > 启动阈值 ──→ 风扇 ON
温度 < 停止阈值 ──→ 风扇 OFF
中间区间        ──→ 保持当前状态
```
并始终保证 `启动阈值 > 停止阈值`，防止临界点频繁启停。

### 非阻塞机制
所有"等待/周期"动作（LED 闪烁、DS18B20 转换、串口上报）都用 TIM3 的 `TickCount`
做时间戳判断，而不是 `Delay_ms` 死等——**主循环永远在转，按键、显示、接收都不被阻塞**。
