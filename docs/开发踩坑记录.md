# 开发踩坑记录（Debug Diary）

> 本项目从 0 到跑通过程中，遇到的每个坑、原因和解决办法。
> 写给以后的自己——嵌入式开发就是不断填坑的过程。

---

## 一、硬件选型与确认阶段

### 坑 1：热敏电阻模块"看起来很高级"，其实不支持通信
- **现象**：拿到 NTC + LM393 模块，以为像 DHT11 那样能读温度数据。
- **真相**：模块只有 **DO（数字量开关）** 和 **AO（模拟量电压）** 两路信号，**没有任何通信协议**（不是 I2C、不是 UART）。
- **办法**：AO 接到 STM32 的 ADC 引脚（PA1），用 ADC 读电压，再用 B 值公式换算成温度。
- **教训**：拿到模块先看引脚定义表，确认它到底输出什么信号，再选 MCU 外设。

### 坑 2：板子晶振是 8MHz 外部晶振，不是默认 HSI
- **现象**：延时函数、PWM 频率和预期对不上。
- **原因**：STM32F103C8T6 板子实际用的是 **8MHz 外部晶振（HSE）**，时钟树配错就全错。
- **办法**：确认 SystemInit 走的是 HSE 8MHz → PLL ×9 → 72MHz 主频。

## 二、ADC 与温度采集

### 坑 3：ADC 用了外部触发，却没配置触发源
- **现象**：ADC 读出来是 0 或乱跳。
- **原因**：初始化时写了"外部触发转换"，但对应的定时器（TIM1）根本没配，没人触发它。
- **办法**：改成**软件触发**：
  ```c
  ADC_InitStruct.ADC_ExternalTrigConv = ADC_ExternalTrigConv_None;
  ```
  转换时调用 `ADC_SoftwareStartConvCmd(ADC1, ENABLE);`

### 坑 4：GetValue() 的返回值没接住
- **现象**：温度显示是随机数（比如 85℃、-10℃）。
- **原因**：代码写成了 `GetValue();`（调用了但没接收返回值），后面却用了另一个未初始化的变量。
- **正确写法**：
  ```c
  uint16_t adc_value = GetValue();   // ★必须接住返回值！
  ```
- **教训**：函数返回值，用不用、怎么用，想清楚。

### 坑 5：局部变量遮蔽（同名变量覆盖）
- **现象**：读数时好时坏。
- **原因**：函数里定义了一个局部 `uint16_t Value;`，把上层同名变量遮住了。
- **办法**：变量名不要重复，内部函数尽量加 `static`。

### 坑 6：温度换算公式（B 值法）
NTC 热敏电阻的换算分三步：
```
① ADC 数字 → 电压：   Vout = 3.3 × ADC / 4095
② 电压    → NTC 电阻： R = 10000 × Vout / (3.3 − Vout)
③ 电阻    → 温度：     1/T = 1/T0 + ln(R/R0)/B
                       T0=298.15(25℃)，R0=10000(25℃阻值)，B=3950
                       最后减 273.15 得到摄氏温度
```
**除零保护**：温度极高时 Vout 接近 3.3V，分母 `(3.3−Vout)` 接近 0，会炸——
```c
if (R_ntc <= 0.0f) R_ntc = 1.0f;
```

## 三、定时器与 PWM（电机）

### 坑 7：TIM1 写成 TIM2，电机不转
- **现象**：电机 PWM 初始化了但不转。
- **原因**：PA3 对应的是 **TIM2_CH4**，代码里却初始化了 TIM1。
- **办法**：每个引脚的复用定时器通道是**固定的**，查数据手册引脚定义。

### 坑 8：TB6612 电机驱动接线
| TB6612 | STM32 | 作用 |
|--------|-------|------|
| PWMA   | PA3 (TIM2_CH4) | PWM 调速 |
| AIN1   | PA4 | 方向 1 |
| AIN2   | PA5 | 方向 2 |
| STBY   | 接 3.3V | 待机脚必须拉高，否则不工作 |
| VM     | 5V | 电机电源 |
| VCC    | 3.3V | 逻辑电源 |
- **关键**：STBY 不接高电平，芯片一直待机——电机死都不转。

### 坑 9：NVIC 没开中断总开关（LED 不闪的元凶）
- **现象**：TIM3 配置了、中断函数也写了，`TickCount` 永远是 0。
- **原因**：只配了定时器中断使能（`TIM_ITConfig`），但 **NVIC 总开关没打开**！
- **关键一行**：
  ```c
  NVIC_EnableIRQ(TIM3_IRQn);   // ★没有这行，中断请求到不了 CPU
  ```

## 四、LED 闪烁（非阻塞）

### 坑 10：用 Delay_ms 做闪烁 = 阻塞卡死
- **错误做法**：
  ```c
  LED_ON(); Delay_ms(500);
  LED_OFF(); Delay_ms(500);
  ```
  主循环卡在延时里，温度读不了、屏幕不刷新。
- **正确思路（非阻塞）**：靠 `TickCount`（每 1ms 中断 +1）做时间戳：
  ```c
  void LED_Twinkle(void) {
      if (TickCount - LastBlinkTime >= 500) {   // 到点了才翻转
          LastBlinkTime = TickCount;
          GPIO_Toggle(LED);
      }
  }
  ```
  主循环每轮调用一次，**绝不死等**。

### 坑 11：`void LED_Twinkle();` 是函数声明，不是调用
- **现象**：LED 死活不闪，中断明明跑通了。
- **原因**：在 main 里写了 `void LED_Twinkle();`——这行末尾带 `;`，编译器认为是"声明一个函数"，**根本没执行**。
- **调用就是**：
  ```c
  LED_Twinkle();   // 不要写 void！
  ```

## 五、OLED 显示

### 坑 12：OLED 显示不了小数
- **现象**：`sprintf("%f")` 输出空白或乱码。
- **原因**：Keil 的 **MicroLIB 不支持 `%f` 浮点格式化**（嵌入式常见坑）。
- **办法**：手写 `OLED_ShowFloat()`——把 float 拆成整数部分和小数部分分别显示，中间插个小数点：
  ```
  25.36 → 整数25 + "." + 小数4（四舍五入）→ "25.4"
  ```

### 坑 13：OLED 软件 I2C 引脚
- SCL = PB8，SDA = PB9，从机地址 0x78。

## 六、代码规范与架构

### 坑 14：Keil 编辑器红色波浪线 ≠ 编译错误
- **现象**：编辑器画一堆红叉，但代码能跑。
- **原因**：Keil 编辑器的 IntelliSense 缓存抽风。
- **标准**：**以 Build Output（0 Error）为准**，红叉不管它。

### 坑 15：业务逻辑耦合进驱动模块
- **反例**：`Motor_ON(温度)` 里写死了"超过 30℃ 转"。
- **问题**：电机模块不该懂温度——以后换 DHT11、改阈值，得改电机驱动。
- **原则**：**驱动只管硬件动作（转/停/亮/灭），业务判断（什么时候转）放 main**。

### 坑 16：重复文件 `Motar.h`（拼写错误）
- 项目里同时存在 `Motar.h`（拼错的）和 `Motor.h`，容易 include 错。
- 删掉废弃文件。

### 坑 17：魔法数字散落
- **反例**：代码里到处是 `30.0`、`28.0`、`50`、`3.3`、`4095`……
- **办法**：全部收进 `config.h`，用宏命名：
  ```c
  #define TEMP_ON_THRESHOLD   30.0f
  #define FAN_SPEED            50
  ```
  改参数只动一个文件。

### 坑 18：互斥分支写成两个独立 if
- **反例**：
  ```c
  if (Flag == 1) { ... }
  if (Flag == 0) { ... }   // 互斥但没写成 if/else
  ```
- **办法**：互斥逻辑一定 `if / else`。

## 八、DS18B20 数字温度传感器

### 坑 21：DS18B20 一直读到 1（无应答）—— GPIO 端口写错
- **现象**：OLED 上温度恒显示 `1`，按手册时序表逐项排查仍无应答。
- **根因**：DS18B20.c 初始化里把端口写成了 `GPIO_Init(GPIOA, ...)`，而 DQ 实际接 **PB1（GPIOB）**——PB1 从未被配置，传感器收不到复位脉冲，自然无应答。
- **办法**：改为 `GPIO_Init(DS18B20_GPIO_PORT, ...)`（端口和引脚都用 config.h 宏）。
- **教训**：① 引脚端口（GPIOA/GPIOB）和引脚号（Pin_x）都要核对，复制代码最容易只改引脚号、忘改端口；② 读到固定值 `1`/`0` 且时序没把握时，优先怀疑"引脚根本没被初始化"。

### 坑 22：单总线必须有上拉电阻
- 单总线设备引脚是**开漏（三态）**，线空闲时没人把电平拉高，必须外接 **4.7kΩ 上拉电阻到 VCC**。
- 用带板模块（板载上拉）可直接用；裸芯片一定要自己加上拉，否则通信失败。

### 坑 23：温度转换不能死等 800ms
- DS18B20 发 `0x44` 后最长要等 750ms 才出结果，`Delay_ms(800)` 会把主循环卡死。
- **办法**：驱动做成三状态状态机（空闲 → 等待转换 → 读取），用 `TickCount` 计时，等待期间主循环照常跑、返回上一次温度。

### 坑 24：命令流程要记牢
```
复位(等应答) → 0xCC 跳过ROM → 0x44 启动转换 → 等待 →
复位 → 0xCC → 0xBE 读暂存器 → 读2字节温度 → raw × 0.0625
```

## 九、JDY-31 蓝牙（SPP 透传）

### 坑 25："写成功但收不到字节"—— TX/RX 接反
- **现象**：手机连接成功、写入成功，但接收区 0 字节。
- **根因**：蓝牙与单片机的两根数据线接反。"写"走的是 `模块TXD→单片机RX` 这根线，写成功只证明这根通；单片机上报走 `单片机TX→模块RXD` 另一根，接反就收不到。
- **正确接法**：
  ```
  单片机 PA9 (TX) ──→ 模块 RXD
  单片机 PA10(RX) ←── 模块 TXD
  ```
- **教训**：串口永远交叉接（TX 对 RX）；一个方向通不代表另一个方向通。

### 坑 26：JDY-31 只能 3.3V 供电
- JDY-31 工作电压 1.8~3.6V，**接 5V 会损坏模块/工作异常**。HC-05 部分版本可 5V，两者不要混为一谈。

### 坑 27：只"配对"没"连接"（Bluetooth Socket failure）
- 系统蓝牙里配对成功，不代表 APP 已建立 SPP 数据连接。
- 报 `Connect failed: Bluetooth Socket failure` 时，**模块断电重新上电**，再在 APP 里重新连接即可。

### 坑 28：运行环境限制
- **安卓模拟器无蓝牙硬件**，搜不到设备，必须真机测试。
- **iPhone 不支持经典蓝牙 SPP**（仅 BLE），JDY-31/HC-05 须用安卓手机。

### 坑 29：温度上报刷屏
- **现象**：主循环每 100ms 发一条，手机每秒收 10 条，疯狂刷屏。
- **办法**：加 `LastSendTime`，用 `TickCount` 控制每隔 `SERIAL_SEND_PERIOD_MS`（默认 1000ms）才发一次，非阻塞、不刷屏。

### 坑 30：协议选型——文本 vs HEX、固定 vs 可变
- 本项目选 **文本模式 + 可变包长（`\n` 结束）**：可读好调试、命令长短随意、蓝牙自带 CRC。
- HEX 固定帧（帧头+地址+命令+长度+数据+校验）留给以后多机、强干扰、大数据场景。

## 总结：嵌入式开发的通用心法

1. **先确认硬件能力**（输出什么信号、接哪个引脚、供电电压），再写代码。
2. **返回值要接住，中断要开 NVIC，定时器通道要对应引脚**。
3. **端口（GPIOA/GPIOB）和引脚号（Pin_x）要一起核对**，复制代码最容易漏改端口。
4. **串口交叉接（TX 对 RX），一个方向通不代表另一个方向通**。
5. **单总线要上拉，开漏引脚自己不会变高**。
6. **阻塞延时只在简单场景用；主循环要非阻塞，用时间戳**。
7. **驱动和业务分层**：驱动管硬件，main 管逻辑。
8. **魔法数字集中管理**（config.h）。
9. **无线功能真机测**：模拟器无蓝牙，SPP 不用 iPhone。
10. **以编译输出为准，别被编辑器红叉吓住**。
