# 开发踩坑记录（Debug Diary）

> 本项目从 0 到跑通过程中，遇到的每个坑、原因和解决办法。
> 写给以后的自己——嵌入式开发就是不断填坑的过程。

---

## 一、硬件选型与确认阶段

### 坑 1：热敏电阻模块"看起来很高级"，其实不支持通信
- **现象**：拿到 NTC + LM393 模块，以为像 DHT11 那样能读温度数据。
- **真相**：模块只有 **DO（数字量开关）** 和 **AO（模拟量电压）** 两路信号，**没有任何通信协议**（不是 I2C、不是 UART）。
- **办法**：AO 接到 STM32 的 ADC 引脚（PA1），用 ADC 读电压，再用 B 值公式换算成温度。
- **教训**：拿到模块先看引脚定义表，确认它到底输出什么信号，再选 MCU 外设。

### 坑 2：板子晶振是 8MHz 外部晶振，不是默认 HSI
- **现象**：延时函数、PWM 频率和预期对不上。
- **原因**：STM32F103C8T6 板子实际用的是 **8MHz 外部晶振（HSE）**，时钟树配错就全错。
- **办法**：确认 SystemInit 走的是 HSE 8MHz → PLL ×9 → 72MHz 主频。

## 二、ADC 与温度采集

### 坑 3：ADC 用了外部触发，却没配置触发源
- **现象**：ADC 读出来是 0 或乱跳。
- **原因**：初始化时写了"外部触发转换"，但对应的定时器（TIM1）根本没配，没人触发它。
- **办法**：改成**软件触发**：
  ```c
  ADC_InitStruct.ADC_ExternalTrigConv = ADC_ExternalTrigConv_None;
  ```
  转换时调用 `ADC_SoftwareStartConvCmd(ADC1, ENABLE);`

### 坑 4：GetValue() 的返回值没接住
- **现象**：温度显示是随机数（比如 85℃、-10℃）。
- **原因**：代码写成了 `GetValue();`（调用了但没接收返回值），后面却用了另一个未初始化的变量。
- **正确写法**：
  ```c
  uint16_t adc_value = GetValue();   // ★必须接住返回值！
  ```
- **教训**：函数返回值，用不用、怎么用，想清楚。

### 坑 5：局部变量遮蔽（同名变量覆盖）
- **现象**：读数时好时坏。
- **原因**：函数里定义了一个局部 `uint16_t Value;`，把上层同名变量遮住了。
- **办法**：变量名不要重复，内部函数尽量加 `static`。

### 坑 6：温度换算公式（B 值法）
NTC 热敏电阻的换算分三步：
```
① ADC 数字 → 电压：   Vout = 3.3 × ADC / 4095
② 电压    → NTC 电阻： R = 10000 × Vout / (3.3 − Vout)
③ 电阻    → 温度：     1/T = 1/T0 + ln(R/R0)/B
                       T0=298.15(25℃)，R0=10000(25℃阻值)，B=3950
                       最后减 273.15 得到摄氏温度
```
**除零保护**：温度极高时 Vout 接近 3.3V，分母 `(3.3−Vout)` 接近 0，会炸——
```c
if (R_ntc <= 0.0f) R_ntc = 1.0f;
```

## 三、定时器与 PWM（电机）

### 坑 7：TIM1 写成 TIM2，电机不转
- **现象**：电机 PWM 初始化了但不转。
- **原因**：PA3 对应的是 **TIM2_CH4**，代码里却初始化了 TIM1。
- **办法**：每个引脚的复用定时器通道是**固定的**，查数据手册引脚定义。

### 坑 8：TB6612 电机驱动接线
| TB6612 | STM32 | 作用 |
|--------|-------|------|
| PWMA   | PA3 (TIM2_CH4) | PWM 调速 |
| AIN1   | PA4 | 方向 1 |
| AIN2   | PA5 | 方向 2 |
| STBY   | 接 3.3V | 待机脚必须拉高，否则不工作 |
| VM     | 5V | 电机电源 |
| VCC    | 3.3V | 逻辑电源 |
- **关键**：STBY 不接高电平，芯片一直待机——电机死都不转。

### 坑 9：NVIC 没开中断总开关（LED 不闪的元凶）
- **现象**：TIM3 配置了、中断函数也写了，`TickCount` 永远是 0。
- **原因**：只配了定时器中断使能（`TIM_ITConfig`），但 **NVIC 总开关没打开**！
- **关键一行**：
  ```c
  NVIC_EnableIRQ(TIM3_IRQn);   // ★没有这行，中断请求到不了 CPU
  ```

## 四、LED 闪烁（非阻塞）

### 坑 10：用 Delay_ms 做闪烁 = 阻塞卡死
- **错误做法**：
  ```c
  LED_ON(); Delay_ms(500);
  LED_OFF(); Delay_ms(500);
  ```
  主循环卡在延时里，温度读不了、屏幕不刷新。
- **正确思路（非阻塞）**：靠 `TickCount`（每 1ms 中断 +1）做时间戳：
  ```c
  void LED_Twinkle(void) {
      if (TickCount - LastBlinkTime >= 500) {   // 到点了才翻转
          LastBlinkTime = TickCount;
          GPIO_Toggle(LED);
      }
  }
  ```
  主循环每轮调用一次，**绝不死等**。

### 坑 11：`void LED_Twinkle();` 是函数声明，不是调用
- **现象**：LED 死活不闪，中断明明跑通了。
- **原因**：在 main 里写了 `void LED_Twinkle();`——这行末尾带 `;`，编译器认为是"声明一个函数"，**根本没执行**。
- **调用就是**：
  ```c
  LED_Twinkle();   // 不要写 void！
  ```

## 五、OLED 显示

### 坑 12：OLED 显示不了小数
- **现象**：`sprintf("%f")` 输出空白或乱码。
- **原因**：Keil 的 **MicroLIB 不支持 `%f` 浮点格式化**（嵌入式常见坑）。
- **办法**：手写 `OLED_ShowFloat()`——把 float 拆成整数部分和小数部分分别显示，中间插个小数点：
  ```
  25.36 → 整数25 + "." + 小数4（四舍五入）→ "25.4"
  ```

### 坑 13：OLED 软件 I2C 引脚
- SCL = PB8，SDA = PB9，从机地址 0x78。

## 六、代码规范与架构

### 坑 14：Keil 编辑器红色波浪线 ≠ 编译错误
- **现象**：编辑器画一堆红叉，但代码能跑。
- **原因**：Keil 编辑器的 IntelliSense 缓存抽风。
- **标准**：**以 Build Output（0 Error）为准**，红叉不管它。

### 坑 15：业务逻辑耦合进驱动模块
- **反例**：`Motor_ON(温度)` 里写死了"超过 30℃ 转"。
- **问题**：电机模块不该懂温度——以后换 DHT11、改阈值，得改电机驱动。
- **原则**：**驱动只管硬件动作（转/停/亮/灭），业务判断（什么时候转）放 main**。

### 坑 16：重复文件 `Motar.h`（拼写错误）
- 项目里同时存在 `Motar.h`（拼错的）和 `Motor.h`，容易 include 错。
- 删掉废弃文件。

### 坑 17：魔法数字散落
- **反例**：代码里到处是 `30.0`、`28.0`、`50`、`3.3`、`4095`……
- **办法**：全部收进 `config.h`，用宏命名：
  ```c
  #define TEMP_ON_THRESHOLD   30.0f
  #define FAN_SPEED            50
  ```
  改参数只动一个文件。

### 坑 18：互斥分支写成两个独立 if
- **反例**：
  ```c
  if (Flag == 1) { ... }
  if (Flag == 0) { ... }   // 互斥但没写成 if/else
  ```
- **办法**：互斥逻辑一定 `if / else`。

## 七、工程配置

### 坑 19：config.h 放哪？
- include path 里有 `.\System`，所以把 `config.h` 放 `System/` 目录，`#include "config.h"` 就能找到。

### 坑 20：.h 文件不用加进 Keil 工程
- 头文件只参与编译展开，不需要在工程文件列表里显式添加。

---

## 总结：嵌入式开发的通用心法

1. **先确认硬件能力**（输出什么信号、接哪个引脚），再写代码。
2. **返回值要接住，中断要开 NVIC，定时器通道要对应引脚**。
3. **阻塞延时只在简单场景用；主循环要非阻塞，用时间戳**。
4. **驱动和业务分层**：驱动管硬件，main 管逻辑。
5. **魔法数字集中管理**（config.h）。
6. **以编译输出为准，别被编辑器红叉吓住**。
